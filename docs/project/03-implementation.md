# 功能实施计划与验收

## 主计划

功能点、依赖、状态及验收以 [Excel 实施计划](../../outputs/2026-11-05-plan/waibu_media_agent_功能实施计划.xlsx) 为主记录，版本 0.1.0。共 44 项：F01–F40 覆盖首版与真实数据试运行，F41–F44 为待启用扩展。当前全部功能未开发，不将设计文件的完成计入产品功能完成率。

Excel 分为五张表：

| 表 | 用途 |
|---|---|
| 总览 | 按阶段汇总任务数量和已完成数 |
| 任务 | 稳定 ID、依赖、状态、负责人、文件范围、互斥锁、分支及验证记录 |
| 功能规格 | 目标、实现说明、完成条件及设计依据 |
| 验收用例 | 每项任务的具体验证场景、预期、执行结果和证据位置 |
| Agent协议 | 领取、并行、单写者回填、验收、阻塞和续跑约定 |

数据表第 5 行为字段名，第 6 行起为数据。ID 不能重排生成或复用。依赖列表用英文分号分隔，空单元格表示无依赖。新增/修改依赖时重新做 DAG 校验，并更新 `dependency_gate` 公式及统计范围；任务领取以实际数据重新计算，不依赖公式缓存。

## 实施顺序

P0 导入固定上游，建立契约、离线环境、数据库、队列和模型适配。共享契约先确定，后续任务可依据 fixture 分头推进；任务的实际领取顺序由依赖图决定，phase 是产品分组，wave 是拓扑提示，均不能代替逐项依赖判断。

P1 建来源、证据、选题和作者材料；P2 建起草、自检、版本和人工批准；P3 建私人审核界面；P4 建封面、排版、复制验证、发布包和日调度；P5 完成联调、恢复验证、部署和试运行。

F18 虽属于 P2，但只依赖基础契约与数据库，应尽早执行，为去重、编辑和导出提供版本能力。前端 F23/F24 可以在契约与鉴权完成后用 fixture 开始，不必等待全部后端。各功能提交独立路由/队列注册片段，F37 由协调者统一接入共享入口，避免争改 `server.ts`、`site/modules/` 和 Dockerfile。

## 开发验证

本仓库当前没有 package.json，下列命令在 F01 引入上游及 F03 配好环境后才可执行。Node 版本和脚本以锁定源码实际声明为准。

```bash
npm ci
npm run typecheck
DATABASE_URL=postgres://127.0.0.1:5432/waibu_test npm test
npm run build -w @aihot/web
npm run test:web
node scripts/smoke.ts --base http://localhost:3000
```

测试连接串仅为本地示例，实际凭据通过环境注入，不写进报告。smoke 需要服务已启动。模块测试纳入上游测试入口，跨进程端到端测试按 F37/F38 补齐，不能用未实现脚本名称宣称已验证。

每个任务先完成表中的行为验收，再测试受影响的上游边界。测试使用本地假供应商和脱敏材料；涉及页面做实际浏览器验证，涉及排版检查真实复制结果；没有运行的测试明确标 NOT_RUN。

## 并行与迭代

只有协调 Agent 写主 Excel，执行 Agent 使用独立 worktree 和 feature 分支。Excel 的 DONE 表示已合并到集成分支且验收通过，执行者自测完成只提交 REVIEW。共享入口、迁移编号和锁文件由协调者串行处理。

任务失败可以自主修复并复测，回填 iteration 和证据。出现新缺陷时新增 FIX 任务并关联父任务，不能把既定验收条件删掉来通过。技术失败、资料不足、缺作者运行凭据分别记录，不伪装成完成。

详细协议见 Excel 及 [交接说明](05-agent-handoff.md)。没有要求当前立即启动并行开发；本次交付仅规划其工作方式。

## 真实运行准入

F40 前需作者提供运行环境、模型凭据和明确预算，完成私人入口、数据库/素材备份及恢复验证。默认采集、模型和外发关闭；不能直接运行会开启开关的上游初始化流程。

观察 7 天真实运行，记录选题重复、事实错误、人工修改量、失败类型及调用消耗；样本规模不足或某日无选题如实记录。不承诺每天都有值得发布的稿件。真实试运行不包含自动发布或消息推送。
